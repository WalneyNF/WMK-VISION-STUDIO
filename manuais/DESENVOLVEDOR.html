Guia técnico para desenvolvedores

1. Objetivo e arquitetura

Uma aplicação web local: Flask recebe uploads e configurações, uma thread executa a inferência YOLO, os resultados do Ultralytics são convertidos em detecções do Supervision e salvos em vídeos/JSON; o frontend consulta o andamento.

Browser (HTML/CSS/JS)
    ⇅ HTTP /api/*
Servidor Flask (app.py)
    ├── uploads/ (vídeos)
    ├── JOBS em memória + thread
    │    └── Ultralytics YOLO + ByteTrack → Supervision
    ├── resultados/ (MP4 + JSON)
    └── logs/ (diagnóstico)

Para protótipo local funciona; em produção, processos de trabalho isolados, fila persistente, autenticação, cotas, limpeza e testes são necessários.

Exemplo: GET http://127.0.0.1:8767/api/saude. As rotas locais não possuem autenticação: não publicar na internet.

4. Exemplo de POST em Python

O usuário primeiro faz upload pelo painel ou API, recebe id, e então inicia o trabalho:

import requests
base = 'http://127.0.0.1:8767'
with open('vehicles.mp4','rb') as arq:
    envio = requests.post(base+'/api/upload', files={'video': arq},timeout=60)
envio.raise_for_status()
identificador = envio.json()['id']
config = {'id': identificador, 'modelo':'yolo11n.pt',
          'confianca':0.35, 'resolucao':416, 'linha':50,
          'intervalo':1, 'dispositivo':'cpu',
          'saida_largura':1280, 'apenas_veiculos':True}
r = requests.post(base+'/api/processar', json=config, timeout=30)
r.raise_for_status()
print('Tarefa:', r.json()['id'])

Este exemplo é ilustrativo e depende da API local em execução. Não use em serviço exposto a usuários desconhecidos.

5. Segurança, desempenho e testes

O servidor aceita até 2 GB por arquivo. Este limite não substitui validação de conteúdo, quotas, restrição de consumo, limpeza de mídia e tratamento de falhas de codec. O uso de threads e o dicionário JOBS em memória não são persistentes; reiniciar o servidor perde o histórico operacional. Use isolamento, SQLite/fila, limites de recursos e autenticação antes de produção.

Teste manual mínimo: abrir página; verificar /api/saude; carregar arquivo inválido (deve ser rejeitado); analisar vídeo curto; conferir contadores, MP4, JSON e log; comparar eventos manualmente com o vídeo.
